# How the numbers are verified

Physics code fails quietly: a wrong factor of two still prints a plausible number. So the rule in this repository is that **no result is trusted because it looks right** - each one is checked against something that does not share its code.

## The layers

| Layer | What it checks | Against |
|---|---|---|
| Reference sweeps | `physmath`: sin, cos, tan, exp, ln, atan, atan2, asin, acos, sinh, cosh, tanh, asinh, acosh, atanh, log1p, cbrt, sqrt, hypot, fractional powers | IEEE-double values from Python's `math`, at hundreds of points per function across the whole range. Worst relative error 6e-16 (`tools/check_physmath.py`). |
| A second implementation | The quantum simulator | `tools/gen_ref_quantum.py`, which builds every gate as a full 2^n x 2^n matrix by explicit Kronecker structure and multiplies. Different algorithm, no shared indexing. 48 random circuits (1-5 qubits, all gates) plus Pauli expectations, Bloch vectors and entanglement entropies agree to 1e-12. |
| High precision | Relativity | 50-digit `decimal` arithmetic on the *exact* input doubles: gamma from beta = 1e-9 to 1 - 1e-12, low-speed kinetic energy, rapidity, the relativistic rocket, weak-field redshift. |
| Closed forms | Algorithms and cosmology | QFT = DFT; Grover = sin^2((2k+1) theta); flat-LCDM age = 2/(3 H0 sqrt(OL)) asinh(sqrt(OL/Om)); matter-only distance = 2c/H0 (1 - 1/sqrt(1+z)); above-barrier tunneling resonance k a = pi gives T = 1; E^2 = (pc)^2 + (mc^2)^2. |
| Physical consistency | Constants | mu0 eps0 c^2 = 1; a0 = hbar/(m_e c alpha); R_inf = alpha^2 m_e c/2h; Compton wavelength; classical electron radius; the Rydberg energy 13.605693122994 eV. |
| Published values | End results | GPS +38.4 microseconds/day; Sun r_s 2.95 km; Earth r_s 8.87 mm; Hawking T of the Sun 6.17e-8 K; hydrogen Balmer lines (air) 656.28 / 486.13 / 434.05 / 410.17 nm; 100 kV electrons 3.70 pm; Pound-Rebka 2.46e-15; Planck-2018 age 13.80 Gyr. |
| Mutation testing | The tests themselves | `tools/mutation_check.py` breaks the code in 28 realistic ways and requires the suite to fail each time. All 28 are caught. |

Run everything with `sh tests/run_tests.sh` (433 checks). The generated reference files in `tests/data_*.lz` are produced by the scripts in `tools/`; CI regenerates them and fails if they change.

## Bugs this process found

Writing the verification found real bugs - some in this library, some in Larzscript itself:

- **Larzscript's built-in `sqrt` is wrong below ~1e-36 and above ~1e36** (`sqrt(1e-47)` returned 8.67e-19 instead of 3.16e-24): a fixed 60-iteration Newton loop started from 1. Atomic-scale physics in SI units lives exactly there; a de Broglie result came out 8 orders of magnitude off. Fixed upstream in [larzscript#17](https://github.com/larz-scripter/larzscript/pull/17); `physmath.sqrt_` is correct on every existing runtime.
- **Larzscript could not lex `1e9` or `6.626e-34`**: `1.0e9` became `1.0` followed by a stray identifier, silently returning 1.0 inside a function - and `larzscript fmt` printed small decimals in exactly that form. Fixed upstream in [larzscript#18](https://github.com/larz-scripter/larzscript/pull/18).
- **Cancellation in `rocket_trip`** (forming 1 + x for tiny x then taking acosh): 4e-12 relative error on short trips. Caught by the 50-digit reference; fixed by carrying x separately.
- **Cancellation in `gravitational_redshift`** (1/f - 1 in weak fields): 1.7e-11. The *plain-float reference had the same flaw*, so only a high-precision reference exposed it.
- **`atanh` lost 2 digits near -1**, **`sinh`/`tanh` lost 1 digit just above the series cutoff**, **comoving distance to z = 1100 was off by 3e-4** with plain Simpson (fixed by integrating in ln(1+z)). All found by sweeps and closed forms.
- **Test-writing mistakes**: reference numbers typed from memory (tunneling probabilities, the "1 g for a year" figures) were wrong while the code was right. The lesson, now a rule: reference values are *generated by an independent program*, never typed.
- **On the website**: every calculator preset is clicked in an automated browser-like test. That run found nine broken presets (dropdown values spelled differently from their options); a static check now fails the build if a preset value is not a real option.

## What is not verified

- **Physics beyond the stated models.** Each result is exact *for its model*: ideal noiseless qubits, the Bohr model (no fine structure or Lamb shift, ~1e-5 error on wavelengths), non-rotating black holes, flat LCDM without radiation. These limits are stated on every page.
- **Constants are CODATA 2018.** CODATA 2022 exists; the differences are in the 8th-10th significant digit for most constants. Updating is one edit to `tools/gen_constants.py`.
- **Real browsers and devices.** The calculator pages are tested with the real WebAssembly interpreter, the real library and the real page scripts in a simulated DOM, and the worker script in an emulated worker, but not in every real browser. Layout on small phones has only been reviewed, not automated.
- **Hardware.** The simulator is a mathematical model; it says nothing about noise, connectivity or gate fidelity of real quantum computers.
- **Not a proof.** Testing shows agreement at the points tested, not correctness everywhere. Bug reports and independent checks are welcome.
